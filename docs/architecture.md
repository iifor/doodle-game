# 模块边界

## React 与实时游戏

`App.jsx` 负责 DOM 容器、当前菜单以及会话挂载和卸载。它通过 `mountShooter(canvas, hudRoot, onScreen)` 创建会话，返回的 `stop()` 停止运行，`dispose()` 完整释放资源。

`ui/screens.js` 把开局、暂停、死亡等少量状态转换交给 React。`ShooterMenu.jsx` 负责菜单内容，`Settings.jsx` 负责受控表单，`Controls.jsx` 负责操作说明。菜单错误以文本显示，不插入任意 HTML。

`ui/hud.js` 直接更新游戏 HUD。坐标、粒子、命中检测和每帧数值不经过 React 状态，避免无意义的组件重渲染。React 只拥有 HUD 的容器，不渲染其子节点。

## 射击会话

`index.js` 是装配入口；`ctx` 是本会话的依赖集合，不挂到 `window`。玩家、敌人及各系统共享同一个场景和碰撞世界。波次、专注斩和补给通过显式方法协作。

`player.js` 处理玩家身体与控制；`weapons/` 处理持枪动画、射击及刀剑；`enemies/` 分离类型、模型、弹道和 AI；`levels/` 分离构建工具及具体地图。调整地图不必进入敌人模型文件，修改菜单不必进入帧循环。

当前是一份 JavaScript ES Modules 工程，静态检查覆盖 JavaScript 与 JSX。没有把迁移中的动态对象伪装成“完整 TypeScript 类型安全”；联机协议在 `online/protocol.js` 中显式校验边界值与消息结构。

## 生命周期和异常

- 只有完成当前帧才安排下一帧，异常后不会继续重复运行坏状态。
- 单机暂停冻结模拟；窗口失焦、隐藏或丢失鼠标锁定会打开菜单。联机只停止本地操作，战场和网络时钟仍运行。切回页面需明确恢复。
- 输入事件使用会话的 `AbortSignal`；React 卸载时结束监听和帧循环。
- 装弹延迟基于游戏时间，不使用脱离会话的后台计时器。
- 重开会重置武器、玩家和效果；临时几何在移除时释放，场景卸载统一释放。
- 存档是射击模块自己的版本化协议。首次启动与损坏存档是不同状态，不能把损坏内容读成默认值。
- 只捕获能清楚处理的失败：输入权限失败明确呈现，初始化失败清理后继续抛出，其余交给应用错误界面停止会话。

## 扩展约定

新增玩法使用独立目录和独立会话，复用 React 应用壳。先按实际需要接入选择菜单，再决定是否需要路由。当前没有空玩法、插件注册器、事件总线、全局状态库或提前搭建的通用游戏引擎。

Mexico 源码作为未开放地图保留；启用前须完成出生点、导航、可破坏物重建及地图资源切换测试，并同步存档允许的地图键。PVP 已通过独立的连接、协议和房主裁定模块接入，具体模块与权限边界见 [联机说明](multiplayer.md)。
