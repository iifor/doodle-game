使用生产构建，向测试页面临时注入标准手柄输入，操作真实游戏循环，没有改写玩家生命、敌人或波次状态：

- 开局：生命 120，Rifle 35/175，第 1 波。
- 持续射击：弹匣 35 → 27；装弹后 35/167。
- 切换 Shotgun 并开火：6 → 5 发；Sniper 瞄准出现瞄准镜；切换 Katana 并挥刀。
- 暂停菜单出现，等待后生命和弹药保持不变；点击恢复回到游戏。
- 返回主菜单并重开：恢复 Rifle 35/175、Shotgun 6/36、生命 120 和第 1 波。
- 修复异步开局与动画帧时间戳混用导致的负时间步后，生产版连续 5 次暂停、返回菜单、重开均成功，恢复 Rifle 35 发且没有错误。
- 开发预览中观察到敌人接近、玩家受伤，以及死亡结算菜单。
- 临时抛出异常，页面显示原始错误和“游戏已停止”，没有继续运行或自动重开。

## 验证边界

嵌入式和受自动化控制的浏览器均拒绝了真实 Pointer Lock 请求，页面明确显示浏览器原因。因此没有把虚拟手柄测试视为真实鼠标捕获或实体手柄验收。需在普通浏览器窗口继续人工验证鼠标手感、音效和完整高波次游玩。

首次手柄操作不能替代浏览器音频授权时，菜单明确要求先点击 START / RESUME，不会停在没有反馈的等待状态。

尚未做长时间资源压力测试、所有特殊移动的逐项浏览器验收、完整 Boss 实战或移动设备兼容性测试。

## 联机移植验收

同日新增联机后，`npm run check` 通过，共 17 项回归检查。新增项覆盖协议边界、竞技场出生点、墙体遮挡、房主伤害裁定、重复击杀、复活生命序号、补给争抢、人数上限、胜负条件、格挡与手雷、远端人物资源释放、连接身份和取消握手。依赖审计结果为 0 个已知漏洞。

使用嵌入式浏览器与 Chrome 两个独立客户端完成真实 WebRTC 验证：

- 本地 PeerServer：创建私人房间，访客通过五位房间码加入，双方人数和昵称一致。
- 开始对局并使用临时虚拟手柄进入：双方生命 110，倒计时一致，能够看到另一名玩家的涂鸦模型。
- 为稳定验证命中，将测试玩家临时放在相距 10 米的无遮挡位置，再通过手柄开火。未修改生命或计分：房主真实步枪射击后，访客生命归零，双方计分为房主 1 杀、访客 1 阵亡；随后访客复活，生命恢复 110，生命序号递增。
- 打开对战菜单时对局继续；房主主动离开后，访客收到明确断线提示。
- 创建公开房间 PUB0，先开始对局再让访客加入；访客正确进入“对局已开始”界面。
- 默认 PeerJS 公共信令服务：在 5180 预览创建私人房间，另一个客户端成功入房，双方名单一致。
- 关闭房间后再次加入原房间码，显示连接失败，没有新建房间或切回单机来掩盖失败。

测试房间已退出。所有临时手柄输入、诊断引用和受控站位仅存在于测试页面，已通过重新加载清除，没有写入游戏源码。

尚未验证不同家庭/运营商网络之间的 NAT 连通、实体手柄、10 台设备同时实战、长时间高延迟环境或专用 TURN 中继。上述双客户端测试不等于跨公网多设备验收。
