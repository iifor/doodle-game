# 创意工坊（自由稿纸建造）落地方案

玩家可在专用稿纸空间里自由建造建筑、捏造人物／怪物形象，操作感对齐「我的世界创造模式」的自由度，但**不使用体素方块**。底层是可序列化的墨件实例（位置／旋转／缩放／墨色），几何复用现有 `builder` 图元与涂鸦部件包。

相关设定：稿房、定稿、初号草稿 —— 见 [第三篇 · 地下稿房](./lore/第三篇-地下稿房.md)、[场景](./lore/场景.md)。开放世界存档与联机边界见 [开放世界](./open-world.md)、[联机说明](./multiplayer.md)。

---

## 1. 目标与非目标

### 目标

- **自由建造**：瞄准放置、拖拽变换、复制删除、撤销重做；可飞、可即时预览。
- **自由捏造**：同一编辑器换角色部件库，组出可保存的形象草稿。
- **定稿进世界**：满意后「定稿」，在营地旁展览或进入私人挑战；探索街区仍由 AI／校验生成。
- **联机一致**：房主权威；访客看到同一份已定稿几何与碰撞。
- **笔触统一**：所有产出仍走墨水渲染，读起来是纸上涂鸦，不是写实模组。

### 非目标（明确不做）

- 体素网格、挖地填坑、无限改写 AI 街区布局。
- 任意三角网格／外部模型导入。
- 多玩家同时抢同一稿纸光标的实时共建（可后期加，V1 不做）。
- 自定义形象直接改写主线兵种数值与平衡（V1 只作皮肤／靶场）。

### 一句话产品定义

> 稿纸上自由摆墨件；定稿后钉进营地。探索城不变，创造欲有出口。

## 2. 玩家体验

### 入口

- 营地内新增可交互点：**稿房门**（橙门或招牌「练习稿」）。
- 靠近按 **E**：进入独立场景「稿纸」（虚拟高度槽或独立场景身份，与住宅室内同级隔离）。
- HUD 文案示例：`稿房 · E 进入练习稿`；内部门口：`E 返回营地`。

### 模式

| 模式 | 说明 |
| --- | --- |
| 游览 | 默认可走可跳；无编辑热键误触 |
| 编辑 | 开飞、显示墨件库与变换手柄；暂停敌人（稿纸内本来无敌） |
| 定稿预览 | 只读碰撞巡视，确认可爬可走后再发布 |

切换：Esc 菜单或快捷键（建议 **B** 开关编辑，可在设置改）。

### 建造操作（建筑）

| 操作 | 输入（初版建议） |
| --- | --- |
| 选件 | 数字键 1–0 / 滚轮切库；屏幕侧栏图标 |
| 放置 | 准星贴地或贴面，左键落下幽灵件 |
| 旋转 | Q / E 绕竖直轴 15°；Shift 精细 5° |
| 缩放 | 滚轮（幽灵件）或选中后滚轮 |
| 吸附 | 默认 0.5 m 网格；**CapsLock** 或菜单关吸附 |
| 选中 | 中键或 V 射线点选 |
| 移动／旋／缩 | 选中后出现轴手柄；也可 WASD + 修饰键微调 |
| 复制 | Ctrl+D |
| 删除 | Delete / Backspace |
| 撤销／重做 | Ctrl+Z / Ctrl+Y |
| 成组／解组 | Ctrl+G / Ctrl+Shift+G |
| 飞行 | 空格升、Ctrl 降（仅编辑模式） |

### 捏造操作（人物／怪）

- 同一套放置与变换；库换成：头、躯干、髋、上臂、前臂、大腿、小腿、手、脚、饰件、武器挂点。
- 强制人形拓扑软约束（可选开关）：必须有且仅有一个 `root`／`hips`／`torso`／`head`，四肢挂到约定插槽，便于套现有动画与命中球。
- V1.5 起：保存为「形象草稿」；可套到本地玩家外观或靶场假人。

### 定稿与展览

1. 菜单「定稿」→ 客户端本地校验件数／包围盒 → 发给房主。
2. 房主再校验、算碰撞、写入存档、回传确认。
3. 营地旁固定「展览桩」生成几何（最多 N 栋，见限额）；玩家可爬可进（若含门洞部件）。
4. 「撤下定稿」回收展览位，蓝图仍留在稿纸存档。

玩家可见说法避免「创意工坊／UGC」等词，用：`练习稿`、`定稿`、`钉在营地边上`。

## 3. 空间与场景

### 稿纸场景

- **身份**：新场景类型 `workshop`（与 `street` / `interior` 并列）。
- **尺寸**：地面约 64×64 m 空白纸面（可后续扩到 96）；四周虚线页边，无蓝色雾墙。
- **隔离**：不占用户外区块坐标；用虚拟高度槽或独立 sceneId（对齐现有室内隔离策略）。
- **内容**：无 AI 请求、无据点、无敌人；可放若干靶架（后期）。
- **光照／渲染**：同一套纸面墨水管线。

### 与现有系统边界

| 系统 | 关系 |
| --- | --- |
| AI 街区生成 | 不调用；不改 `chunks/*.json` 探索布局 |
| 住宅室内 | 不复用住宅 JSON；稿纸自有格式 |
| 据点／任务 | V1 不挂任务强制；可选 Q 支线「去稿房练一笔」 |
| 补给 | 稿纸内不耗弹；展览区战斗规则同营地（安全） |

## 4. 数据模型

### 目录

```text
world-data/<世界 UUID>/
  workshop/
    paper.json           # 当前练习稿（未定稿也可自动保存）
    blueprints/
      <blueprintId>.json # 命名蓝图／形象草稿
    exhibits/
      manifest.json      # 营地展览位占用与 blueprintId 映射
```

`progress.json` 增加可选字段（缺省兼容旧档）：

```json
{
  "workshop": {
    "activeBlueprintId": null,
    "exhibitSlots": [{ "slot": 0, "blueprintId": "…", "placedAt": 0 }]
  }
}
```

### 墨件实例

```json
{
  "schemaVersion": 1,
  "kind": "structure",
  "id": "bp_…",
  "name": "未命名草稿",
  "updatedAt": 0,
  "units": [
    {
      "uid": "u1",
      "part": "slab",
      "ink": "blue",
      "pos": [0, 0, 0],
      "rot": [0, 0, 0],
      "scale": [4, 1, 4],
      "group": null,
      "flags": { "noCollide": false }
    }
  ],
  "groups": [{ "id": "g1", "name": "南墙", "children": ["u1", "u2"] }],
  "meta": { "bounds": { "min": […], "max": […] }, "unitCount": 12 }
}
```

形象草稿 `kind: "figure"`，`part` 取角色库 id，并带 `socket`（如 `head`、`arm.L`）。

### 部件目录（V1 建筑底料）

| part id | 含义 | 碰撞 | 来源 |
| --- | --- | --- | --- |
| `box` | 实心块 | 有 | `builder.box` |
| `slab` | 楼板／地面片 | 有 | `builder.slab` |
| `wallX` / `wallZ` | 带可选门洞的墙段 | 有 | `builder.wall*` |
| `rail` | 栏杆 | 有／薄 | `builder.rail` |
| `stairFlight` | 一段折返／直跑踏步 | 有 | 抽自 `parts.js` 楼梯 |
| `column` | 柱 | 有 | box 预设 |
| `crate` | 货箱 | 有 | 现成尺寸 |
| `windowBay` | 窗贴面 | 无 | 装饰 |
| `doorGap` | 门洞标记（与墙组合） | 无 | 编辑辅助 |

V1.5 角色底料：复用 `enemies/models.js` 的 blob／noodle／mitten／shoe 等为可摆 part，输出仍生成 `parts` 挂点字典以便命中。

### 限额（房主校验）

| 项 | V1 上限 |
| --- | --- |
| 单蓝图 ink 件数 | 256 |
| 成组嵌套深度 | 3 |
| 包围盒边长 | ≤ 48 m |
| 世界已定稿展览 | 4 |
| 蓝图文件数／世界 | 32 |
| 单文件序列化 | ≤ 256 KiB |
| 撤销栈 | 64 步（仅内存，不落盘逐步） |

超限拒绝定稿并给出中文原因（与 `requireWorld` 风格一致）。

## 5. 模块划分（代码落点）

新建目录，避免把编辑器逻辑塞进 `session.js`：

```text
src/games/shooter/workshop/
  catalog.js      # 部件目录、默认尺寸、图标元数据
  schema.js       # 校验 blueprint JSON、限额、规范化
  paper.js        # 稿纸场景构建（地面、页边、展览无关）
  editor.js       # 放置、点选、变换、撤销、成组
  build.js        # units[] → builder 几何 + 碰撞
  figure.js       # 形象草稿 → 涂鸦模型挂点（V1.5）
  exhibit.js      # 营地展览桩挂载／卸载
  session-api.js  # 供 exploration/session 调用的窄接口
```

服务端：

```text
server/workshop-store.js   # 读写 workshop/，校验，与 world-store 挂接
```

联机协议（`online/protocol.js` 增消息，均经房主）：

| 消息 | 方向 | 作用 |
| --- | --- | --- |
| `workshop.enter` / `workshop.leave` | C→H / H→C | 场景切换确认 |
| `workshop.sync` | H→C | 下发当前 paper 快照（进房或定稿后） |
| `workshop.edit` | C→H | 增量编辑操作（仅房主编辑 V1；访客只读） |
| `workshop.publish` | C→H | 请求定稿到展览槽 |
| `workshop.unpublish` | C→H | 撤下 |

**V1 权限**：仅房主可编辑与定稿；访客可进稿纸只读观看。避免首版做操作变换合并。

### 复用关系

- 几何：**只**通过 `createBuilder` 图元与抽离的 stair 段生成，禁止编辑器直接 `new Mesh` 绕过碰撞。
- 场景切换：对齐现有室内 `scenes.js` 的确认／取消／序号隔离。
- 渲染：墨色枚举沿用 `INK.*`；新墨色需改渲染与协议，V1 不新增。

## 6. 分阶段交付

### V1 — 建筑稿纸（建议首发）

**范围**

- 营地稿房门 → 稿纸场景。
- 建筑底料库 + 编辑模式全套操作（放置／变换／删／复制／撤销／成组）。
- `paper.json` 自动保存（节流 2s；退出时强制 flush）。
- 定稿到营地展览桩（最多 4）；可撤下。
- 房主编辑、访客只读；联机场景同步。
- 单机／世界测试与限额校验测试。

**验收**

- 房主建造一座可爬上屋顶的简易楼（含楼梯段），定稿后重进世界几何与碰撞一致。
- 杀进程重启，paper 与 exhibit 均恢复。
- 访客加入后看到同一展览；进稿纸只读，不能改。
- `npm run check` 含 schema／限额／build 往返测试；无 AI 费用。

**不做**：形象捏造、访客共建、任务强制绑定、自定义件进探索遭遇。

### V1.5 — 形象草稿

- 角色部件库 + socket 约束。
- 保存 `kind: "figure"`；营地假人架展示；可选「套到我的外观」（仅本地或房间内皮肤同步）。
- 命中球由 socket 自动生成（头／躯干／四肢），禁止玩家调血量。

### V2 — 深化（可选）

- 访客申请编辑权／操作队列。
- 定稿蓝图用作仓库挑战皮肤或私人靶场波次。
- 部件市场仅限本世界导入导出（文件交换，不做正联网）。
- 有限「涂墨笔刷」挤出墙体（仍落成 `box`/`slab` 实例，不是体素）。

## 7. 营地展览布局

- 营地 `0,0` 预留东南侧空地为展览带（固定世界坐标，不跑 AI 重roll）。
- 4 个槽位：中心间距 ≥ 14 m，每槽底板 10×10 m，朝向营地中心。
- 定稿时把蓝图包围盒底面对齐槽位地面；超高裁切提示或拒绝（高 ≤ 24 m）。
- 展览区保持营地安全规则：无敌人刷新、可钩索、可爬。

旧存档无展览带：首次加载稿房功能时在营地布局上**追加**固定 marker（不改已有建筑坐标）；若空地被占，降级为「仅稿纸内存、暂不可钉营地」并提示。

## 8. 校验与安全

- 所有写路径：临时文件 + 原子替换（与现有 world-store 一致）。
- 客户端提交的 `units` 不可信：服务端／房主重跑 `workshop/schema.js`。
- `part` 必须在白名单；`scale` 分量夹紧（如 0.25–16）；禁止 NaN／Inf。
- 定稿 build 失败（如墙洞退化）→ 拒绝并保留旧展览。
- 不计 DeepSeek 费用；不把蓝图送进模型提示。

---

## 9. UI 与文案

- 侧栏：部件分类（结构／楼梯／装饰）。
- 顶栏：草稿名、件数、是否未保存、展览占用 `2/4`。
- 菜单：保存蓝图副本、加载蓝图、定稿、撤下、返回营地。
- 错误：`件数超过 256`、`展览位已满`、`只有房主能定稿` —— 短句，不提内部 schema。

## 11. 实现顺序（工程切片）

1. `workshop/schema.js` + 测试（无 UI）。
2. `build.js`：units → builder；命令行／测试生成一栋楼。
3. `paper.js` + 营地门 + `scenes` 进出（单机）。
4. `editor.js` 最小闭环：选 box／slab、放置、删除、撤销。
5. 变换手柄与吸附；自动保存 `paper.json`。
6. 定稿 + `exhibit.js` 挂营地。
7. 联机同步与权限。
8. 打磨 HUD／菜单文案；补 verification 条目。
9. （另里程碑）V1.5 figure 库。

预估（单人熟悉本仓库）：V1 约 1.5–2.5 周；V1.5 约 +3–5 天。以实际联调联机为准。

## 12. 开放问题（实现前拍板）

1. **编辑权**：确认 V1 仅房主编辑（本文默认）。
2. **稿纸尺寸**：64 m 是否够；是否允许多页 `paper` 分页。
3. **展览与旧营地冲突**：空地不足时是扩大营地标记还是仅允许「世界菜单里的幽灵预览」。
4. **形象是否进 PVP／开放世界他人视野**：V1.5 建议先本地＋同房皮肤，不做跨世界持久时装。
