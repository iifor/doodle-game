# 开放世界（PC）

房主在电脑上创建并保存世界，最多 10 人合作探索。生存和自由混战入口继续保留。本次只交付 PC 键鼠玩法，不增加手机适配。

## 持续世界的 AI 住宅

V1 持续世界的部分方块建筑现在有橙色住宅门。靠近门按 **E**：首次显示准备动画并向 AI 请求室内，成功保存后进入；室内入口按 **E** 返回原来的建筑门外。等待时再次按 E 或离开门口可以取消进入，已经启动的生成完成后仍保存，避免浪费。失败时留在原场景并显示原因，靠近门可重试。不会在路过住宅时提前调用模型。

AI 自主选择一至三层、每层走廊左右各一至三个房间、房间用途、外窗、相邻房间连通门、宽深和配色。一层必须有客厅和厨房；其余可为卧室、浴室、书房、餐厅或储藏室。引擎把这些设计搭成真正有碰撞的墙、门洞、楼板、连续楼梯和用途对应的方块家具。当前使用规则化走廊布局确保每间房可到达，并非任意形状的自由三维建模。室内是独立空间，宽 20/24/28 米、深 24/28/32 米，不要求与方块外壳体积一比一；外窗可见纸面背景，暂不实时显示外面的街区。住宅内暂不生成敌人或交互家具。

缓存路径为 `world-data/<世界 UUID>/interiors/house_<区块X>_<区块Z>_<建筑序号>.json`。同一栋建筑由保存后的外观序号稳定识别，同一房主下的并发进入共用一次生成；写入成功后，重复进入、退出游戏、服务重启及暂停生成均读取缓存。缓存带版本和 SHA-256，损坏时拒绝加载并保留原文件，不自动覆盖。旧版 V2 小区域仍使用原模板规则。

无限世界的室内复用所在区块的水平坐标，在独立的虚拟高度槽位内隔离渲染和碰撞，不预占任何户外区块。场景切换由房主确认，访客收到并校验完整室内后才传送，延迟的确认、取消和错误消息按进入序号隔离。室内卸载几何后仍保留磁盘缓存。武器、血量和弹药沿用进门前的状态。

自动验收见 `tests/interiors.test.js`：生成去重、重启缓存、暂停与损坏存档、实际碰撞上下三层楼、房间通路、窗户防穿出以及联机加载确认。显式运行 `node scripts/check-house-live.js` 会产生一栋住宅的真实模型费用（最多一次纠错重试），使用独立测试目录；不会进入常规测试。2026-09-08 的真实验收生成“墨韵居”，两层共七间房，使用 717 tokens；关闭生成能力并重启存储实例后，读取同一校验和成功。浏览器可加载测试世界，嵌入式环境拒绝 Pointer Lock，尚未取得键鼠实玩进出门的通过证据；已另外检查相同缓存的游戏渲染画面。

## 启动与密钥

使用 Node.js 20.15+。先安装依赖并构建：

```sh
npm ci
npm run build
```

把 `DEEPSEEK_API_KEY` 设置为**启动服务进程的环境变量**，然后运行：

```sh
npm run world
```

也可以自行创建被 Git 忽略的 `.env.local`，内容为 `DEEPSEEK_API_KEY=你的密钥`，使用 Node 原生环境文件支持启动：

```sh
node --env-file=.env.local server/world-server.js
```

`npm run world` 现在自动读取项目根目录的 `.env.local`（环境变量仍优先）；文件不存在时也能启动并读取旧存档。密钥不放入 `VITE_` 变量，不进入浏览器或发给朋友。新建入口使用持续探索模式，创建时必须由 AI 生成至少四栋营地建筑；配置或生成失败会明确报错，不再自动创建空白营地。已有空营地存档会在进入前预先生成相邻街区，不覆盖已保存地图。无密钥时可读取已经生成的内容，新区域无法生成。

用普通桌面浏览器打开 <http://127.0.0.1:8787>，点击“开始开放世界”。嵌入式浏览器可能拒绝鼠标捕获，需要在正常浏览器窗口游玩。

| 环境变量           | 默认值                    | 用途                         |
| ------------------ | ------------------------- | ---------------------------- |
| `DEEPSEEK_API_KEY` | 未设置                    | 新区域生成凭据               |
| `DEEPSEEK_MODEL`   | `deepseek-v4-flash`       | 生成模型                     |
| `WORLD_DATA_DIR`   | 当前目录下的 `world-data` | 持久存档目录，可设置绝对路径 |
| `WORLD_PORT`       | `8787`                    | 本机服务端口                 |

接口固定使用 `https://api.deepseek.com/chat/completions`，关闭思考模式，启用 `json_object`，提示提供 JSON 示例。依据 [Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/)和[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。返回内容仍须经过地图校验。每次请求超时 60 秒，暂时错误或地图错误最多重试一次；401、402 不重试。终端记录耗时、错误和 token 使用量。

## 持续探索（默认）

新世界使用无限区块协议（schemaVersion 1 + aiGenerated），不设置 2×2 的游戏地图限制。区块按探索方向与距离提前请求，站在区块中心也会准备周围区域；每次最多四个排队请求，服务端最多两个并发生成。生成完成、校验并落盘后才开放通行，失败不会用空地图冒充 AI 结果。每个新生成区块至少四栋建筑，营地外的遭遇随机包含 1～8 名敌人，出生点分散在可通行道路附近，点间至少 12 米；按各自距离和延迟错开激活，同区两次出现至少间隔 0.8 秒，不在玩家 10 米内出生。武器通过随机搭配现有步兵、突袭者、重装、狙击手、盾兵，覆盖步枪、近战刀、霰弹枪、狙击枪和手枪。

数量、位置和兵种由世界种子确定并存入区块，不增加 AI 请求，重新进入不会重新抽签。旧持续世界在房主重新打开时升级尚无击杀进度的据点；原区块保存在 `encounter-backups`，建筑和道路保持原样。已有击杀进度或已清理的据点保留原阵容和进度。V2 模板存档继续使用原四人挑战。

首次进入会预先准备北侧和东侧街区，只有加载了建筑和敌人据点才允许房主开始探索。后续在玩家周围保持 3×3 可见区块，远处释放几何，探索布局永久保存。地面使用连续纸面，移除蓝色边界墙；模型还未完成时会有临时加载阻挡，HUD 显示生成或失败状态。这是按需扩展的世界，不是预先生成无限内容；磁盘、坐标安全范围和模型费用仍是实际限制。

## 归档 V2 小区域与建筑模板

既有 V2 存档使用：2×2 个 128 米区块，共 256×256 米。营地、两个街坊与仓库街区通过固定主路连接，边界不会继续请求生成。共有七栋可进入建筑：两间小商店、两间转角商店、两栋住宅、一座仓库；营地有遮雨棚和补给标识。

创建时生成并保存世界背景和两个街坊的主题。道路、地块、建筑尺寸及入口由程序确定，AI 只调整名称、招牌、蓝／绿／橙配色、雨棚／条纹装饰，以及四个家具槽位。四套单层模板固定通道与出口。商店用于探索，没有交易系统。营地补给标志附近按 E 可补充现有规则的弹药与一枚手雷，每名玩家每 10 秒可领取一次；由房主校验位置和冷却，重复消息不会重复领取。

靠近建筑入口 22 米时只预取最近建筑的室内。首次准备需要生成、验证和保存；以后读取同一布局。门外 6 米内按 **E** 进入，室内入口处按 **E** 返回。准备时可以走开，走开、死亡或断线会取消进入；成功生成的文件仍保留。进入前必须完成房主与客户端加载确认。切换保留生命、武器、弹药，投出的手雷仍由房主在原场景结算。

普通建筑内部安全。仓库有两名步兵、一名突袭者和一名狙击手，同房间玩家共享挑战轮次。室内无人、没有投射物、没有待保存进度时，在仓库门外按 **N** 重置；重置只改变挑战状态，不调用 AI、不改布局。每轮清理落盘后，给当时仍存活且在仓库内的玩家一次补给。阵亡返回室外安全据点，仓库不是复活点。

界面标注“持续探索”的 V1 存档继续区块探索，不自动迁移或加入室内。V2 标注“旧版小区域”，保留七栋室内建筑和旧边界规则。两个版本均可在新版客户端继续；旧客户端不能加入新版房间。

## 创建、探索和合作

1. 填写昵称和世界名称，创建世界；也可以点击已有存档继续。
2. 点击“进入城镇”。WASD 移动，鼠标瞄准，左键开火，右键开镜或格挡，空格跳跃，Q 钩索，E 交互，F 快速挥刀，G 手雷，1–4 或滚轮切换武器。
3. 移动前便预取周围街区，生成、校验、落盘完成后解除临时加载阻挡。持续探索模式没有固定地图尽头，也不显示蓝色雾墙。失败时打开 Esc 菜单选择“重试生成／保存”。
4. 除营地外，每个户外区块一个据点；持续世界使用上述随机遭遇，V2 和已有击杀记录的旧据点保留两名步兵、一名突袭者和一名狙击手。敌人留在本区。队友间没有伤害；敌人伤害、枪械、近战、钩索拉拽及手雷由房主裁定。
5. 击败敌人逐次保存；本据点实际数量的敌人全部击败且保存成功后据点永久安全，发放一次补给。HUD 按实际总数显示清理进度。剩余敌人卸载后再次激活时恢复初始生命。阵亡返回最近已清理据点，否则返回营地。
6. Esc 打开世界菜单，点击“邀请朋友”，把五位房间码发给朋友。朋友打开**同版本游戏**并从开放世界入口加入，无需密钥或房主电脑的 HTTP 地址。可以用各自的本机服务或同版本静态站点；信令配置沿用 [联机说明](multiplayer.md)。
7. 房主选择“保存并退出”，保存安全位置并关闭房间。继续世界恢复保存的安全位置，重新加入的访客从营地出发。

联机菜单不会暂停战斗，房主必须保持页面运行。后台页面被浏览器挂起或心跳中断时房间可能关闭；不支持房主迁移。生成暂停按钮阻止新的请求，已经发送给模型的请求可能仍会完成并计费。

HUD 显示区域、据点、挑战轮次、生成和保存状态及入口操作提示；V2 简易地图显示整个小区域的已探索部分、建筑与队友，室内玩家标在对应建筑入口。每人只显示自身周围 3×3 区块，房主保留所有玩家附近碰撞和敌人模拟；投射物占用的区块延后卸载。远处几何和敌人释放，布局仍保留在磁盘。轻量探索目录和进度留在内存，规模随已探索数量增长。

## 存档与备份

```text
world-data/
  .service.lock
  <世界 UUID>/
    world.json           # 名称、种子、版本；V2 还保存世界背景和街坊主题
    progress.json        # 递增版本、户外进度、仓库挑战轮次、奖励、安全位置、生成开关
    chunks/
      0,0.json           # 营地完整布局及 SHA-256
      1,0.json           # 户外街区，永不因重访重新生成
      8,0.json           # V2 第一栋建筑室内；建筑编号与模板版本在布局内
      26,0.json          # V2 仓库室内；挑战进度另存于 progress.json
```

布局使用“区块坐标＋区块内位置”，渲染切换局部原点。V2 的室内采用七个相互隔离的固定场景槽位，复用现有区块碰撞和导航；这些存储坐标不能通过走路或客户端自报位置进入。场景身份与递增切换序号参与移动、交互和战斗校验。地图分片通过校验后才可进入，旧场景消息被丢弃。

存档保留模板编号、模板版本、AI 参数和展开后的完整布局。版本 1 的模板目录及展开规则是归档格式，后续改几何必须增加模板／生成器版本，不能修改归档规则。读取损坏布局时拒绝加载，不重生成覆盖。每次模型请求只包含当前所需设定和模板参数，序列化输入最多 64 KiB，输出最多 6000 tokens；不累积聊天历史。所有生成层共享最多两个并发调用，进入请求优先于排队预取。

V1 的共享边界出口由种子和边界坐标决定，保留原有字段、数量、重叠、出生空间、道路连通与步行可达性验证。V2 使用固定合法地块与家具槽位，并用真实碰撞和导航测试覆盖所有模板与家具类型。

所有 JSON 写入临时文件、同步后原子替换；POSIX 系统还同步父目录。同一个数据目录只允许一个服务进程，同一个世界只允许一个活跃房主，租约 30 秒，正常每 10 秒续期。进度使用版本比较及顺序写入，已保存击败与奖励不能回退。世界文件与浏览器缓存无关，清理浏览器不会删地图。

备份前使用“保存并退出”，停止本机服务，再复制整个世界 UUID 文件夹到其它磁盘。恢复时停止服务，保留当前文件的副本，然后恢复整套备份。不要混用不同时间的进度和区块文件，不要只保存种子。模型版本调整不改变已有区块；未来修改布局格式时需要显式迁移，不会静默覆盖。

## 沿途地形与街道细节

持续开放世界的道路现在有灰色路面、中心虚线和斑马线。斑马线画在真实路口的进车方向并向后让出一段距离，没有交叉口的街道只在中段画一条，不再覆盖路口本身。

每块街区按类别配额放置浅水坑、施工路障、双面路牌、土堆、碎石和草丛，实测平均 34 处（29–44），其中土堆约 3 处、水坑约 4 处、路牌约 4 块，其余是碎石和草丛；拥挤街区会减少数量。路牌和路障属于街道设施，只沿道路布置且贴在路肩外 1.5～3 米；牌面朝向自己所属的街道，南北向道路的路牌不再被侧着看。路牌文案共 8 种。水坑铺在路面上，是可直接穿行的浅水视觉层，暂不模拟游泳、减速或水流；土堆高 0.8～1.2 米，采用可踩上的低台阶，路障与碎石有真实碰撞并能挡子弹。

这些细节由已缓存的街区布局和坐标稳定推导，适用于旧街区，无额外模型请求，不改写原有建筑、击杀进度或存档。生成时保留道路净空、区块接缝、出生和补给点，以及原地图通往住宅入口的路径。室内与 V2 模板地图保留各自布局。所有联机玩家需要刷新到同一版本，保证新增碰撞一致；远处区块卸载时同时释放地形几何和碰撞。

## 故障处理

- **未配置密钥／401／402**：在服务端配置正确凭据或处理账户状态，然后重新启动服务并刷新页面。已保存区域可继续使用。
- **生成超时／地图无效**：区域保持关闭。稍后用菜单重试；并发相同区块只调用一次，全服务最多同时生成两块。
- **未保存／磁盘已满／无写入权限**：停止继续战斗，释放空间或修复目录权限，再点击重试。未保存的据点不确认清理和奖励，退出会提示先保存。不要删除旧文件来消除错误。
- **地图校验失败／存档版本不兼容**：保留原文件，从备份恢复或排查。不会自动重画覆盖现有地图。
- **已有活跃房主**：关闭另一房主页面或等租约到期。服务重启后重新打开世界。进程锁报错时先确认原进程是否仍在运行，不要在运行期间手工删除锁。
- **无法加入／房主离线**：确认双方版本和房间码一致、房主页面仍在运行，并排查信令与 WebRTC 网络。某些网络需要配置 TURN，首版沿用现有连接限制。
- **鼠标捕获失败**：用普通 PC 浏览器窗口并点击进入按钮；不通过脚本绕过浏览器限制。

服务仅监听回环地址，检查 Host、Origin 和本机会话。不要将生成和写档接口暴露到公网；朋友的地图通过 WebRTC 分片传输并校验，不能直接发起远程付费生成。

## 验证

`npm run check` 运行完整检查；旧版开放世界测试在 `tests/world.test.js`，小区域与模板测试在 `tests/region.test.js`。实际联调结果与尚未完成的真实环境验收见 [验证记录](verification.md#开放世界pc验证)。

要显式复测真实服务，可运行：

```sh
node --env-file=.env.local scripts/check-world-live.js
```

此命令会产生真实模型调用费用，最多生成 3 个新区块，每块仍最多自动重试一次；不会加入常规 `npm run check`。测试使用独立存档目录，输出生成耗时、用量、失败原因，并验证请求去重、道路通行和重启读取。报告与模型地图 JSON 保存在输出的 `world-data/live-check-*` 目录中，不包含密钥。

### V2 真实生成复测

